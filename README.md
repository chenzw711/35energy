## 3. 部署（Cloudflare Pages，10 分钟）

### 方式 A：网页上传
1. Cloudflare 控制台 → Workers & Pages → Create → Pages → **Upload assets**
2. 把整个 `35energy` 文件夹拖进去
3. Deploy
4. 项目 → Custom domains → 绑定 `35energy.com` 和 `www.35energy.com`
5. DNS 用 Cloudflare 托管（域名注册商处把 NS 改成 Cloudflare 分配的两个）

### 方式 B：命令行
```powershell
cd C:\Users\31175\WorkBuddy\2026-11-27-10-48-17
npx wrangler pages deploy ./35energy --project-name=35energy
```

证书由 Cloudflare 自动签发。`_headers` 里的 HSTS、X-Frame-Options 等会生效。

**备选**：Netlify（同样支持 `_headers`）、Vercel（需改成 `vercel.json`）。

## 4. 上线前必须处理的 4 个阻塞项

**这一版可以内部评审、可以给客户看，但现在不能公开上线。** 以下 4 项不解决，站上线即是风险：

### ① 表单没有后端
`contact.html` 和 `resources.html` 的表单目前是**前端模拟成功**——数据没有发到任何地方。

三种接法，按成本排序：

| 方案 | 成本 | 说明 |
|---|---|---|
| HubSpot 免费表单 | ¥0 | 把 `<form>` 换成 HubSpot embed 代码，自带 CRM 和邮件通知 |
| Formspree | 约 ¥60/月 | 改 `action` 属性即可，5 分钟 |
| Cloudflare Worker + Resend | ¥0（少量） | 最干净，需要写 30 行 Worker |

**在接好后端之前，不要投放任何广告。**

### ② 邮箱必须先开通
站内出现了 4 个邮箱，全部尚未确认存在：

- `sales@35energy.com` — 销售主入口（首页、页脚、所有 CTA）
- `cells@35energy.com` — 电池片/OEM
- `compliance@35energy.com` — 合规文档
- `privacy@35energy.com` — GDPR 数据主体请求

**`privacy@` 是法律要求**，GDPR 下必须有一个可用的数据主体请求通道。建议用 Cloudflare Email Routing（免费）转发到现有邮箱，或直接用企业邮箱开通。

### ③ 认证表述必须质量部核对
站上的认证写法是刻意保守的：

- 首页只写标准名称（`IEC 61215 design qualification`），**没有写"已认证"**
- `resources.html` 的市场准入表里，印度/美国/日本写的是 **"Not currently"**
- 所有证书都标"on request"，不展示证书编号

**这套写法是基于"公司尚未公开宣称这些认证"推断的，不是事实核查。** 请质量部逐条确认：

- [ ] IEC 61215 / 61730 是哪家机构出的？证书编号？覆盖哪些型号？有效期到什么时候？
- [ ] CE 的 DoC 是否已签署？覆盖 LVD / EMC / RoHS / REACH 哪些指令？
- [ ] ISO 9001 证书号与认证机构？
- [ ] UKCA / INMETRO / AS-NZS 是否已有，还是确实没有？
- [ ] 印度 BIS / ALMM、美国 UL 是否确实不可供？

如果实际已有更多认证，`resources.html` 的表格要改（那是转化率最高的一块内容）。如果某些写"Supported"的市场实际没有，**必须删掉**——那是虚假陈述。

### ④ legal.html 必须过法务
GDPR 部分的法定义务是真实的，不能自己写：

- [ ] 是否需要指定 **EU 代表**（GDPR 第 27 条）——向欧盟销售但无欧盟实体的公司需要
- [ ] 数据跨境传输的合法性基础（SCC 是否已签）
- [ ] 数据保留期是否与实际操作一致
- [ ] 供应链声明（Modern Slavery）需董事会批准后才能挂"Approved by the board"
- [ ] 上市公司信披口径：站上引用了 2025 年外销占比 28.69%（来自投资者关系记录），确认可公开引用

## 4.5 三份产品手册里的数据冲突（必须确认）

从 `琏升G12-0BB异质结电池.pdf`、`立式储能.pdf`、`曜幕光伏墙.pdf` 提取数据时发现三处不一致。页面上的处理方式已经做了规避，但需要质量部/市场部给最终口径。

### ① 电池效率：26.5%+ 还是 26.0%？

| 来源 | 说法 |
|---|---|
| 手册第 1 页 | **26.5%+ 量产效率平均达** |
| 手册第 2 页电性能表 | 8 个档位 LS-210M-253~260，效率 **25.30%–26.00%** |
| 国内站现有表述 | **26%+** |

**当前处理**：首页和电池页主标用 **26.5%+**（跟手册首页的对外口径），电池页分档表照抄 25.3–26.0%，表注说明"分档为 LS-210M 系列标准档位"。

**问题**：两个数字并列时读者会困惑——到底 26.5 是产品能力还是 26.0 是上限？

**请确认**：26.5% 是新一代产品、26.0 档位之上的未公开档，还是手册首页写大了？

### ② 电池片规格：厚度到底 100 还是 110 μm？

| 来源 | 规格 | 厚度 |
|---|---|---|
| 官方手册 | 210.1 × 105.05 mm **半片** | **110±15 / 120±15 μm** |
| 国内站组件页 | 210 × 52.5 mm（四分片） | **100 μm** |

长宽可以并存（出厂半片 → 组件端再分切成 52.5 宽），**但硅片厚度 100 vs 110 是真冲突**。

**当前处理**：电池页按手册写 210.1×105.05 半片、110 μm；组件页保留 210×52.5。首屏 hero 写的是 110 μm。

**请确认**：量产主流厚度是 100 还是 110？如果是 100，hero 和电池页要一起改回去。

### ③ 光伏墙电气参数不自洽

手册第 2 页：Pmax 88 W，Vmp 6.88 V，Imp 16.12 A，Voc 8.25 V，Isc 16.69 A。

- 6.88 V × 16.12 A = **110.9 W**，和 88 W 差 26%
- Voc 8.25 V **小于** Vmp 6.88 V，不符常理（Voc 必然大于 Vmp）

**当前处理**：页面上**不列** Vmp / Imp / Voc / Isc，只列能自洽的三项：88 W、20.83%、208 W/m²（88 ÷ 0.4224 m² = 208.3 ✓）。电气细节写"随项目 datasheet 提供"。

**请确认**：是不是手册那一列排版错位（比如 Imp 应该是 12.79 A）？确认后补进去——这张表是幕墙客户第一眼要看的东西，缺了会显得不专业。

## 6. 内容策略说明（为什么这么写）

三处刻意的选择，供评审时参考：

**① 不打"全球领先"，打"高温高辐照最优解"**
全站的主线是 −0.24%/°C 这一个数字。因为"效率高"是所有厂都能说的话，而温度系数可以用曲线算给客户看（`technology.html` 的折线图是按真实系数计算的，不是示意图）。

**② 主动说自己的短板**
- `company.html`：明写"三岁公司，bankability 质疑是合理的"
- `technology.html`：对比表里写"HJT 产线 capex 更高、市场供应成熟度不如 TOPCon"
- `modules.html`：明写大版型不适合户用改造
- `resources.html`：印度/美国/日本直接写"Not currently"

这是 B2B 打法。采购方见惯了吹牛的供应商，主动承认边界的反而更容易被当成可靠信源。也让销售在第一次通话时不用花时间纠正预期。

**③ 认证只写标准名，不挂徽章**
没有一张 TÜV/UL 的 logo。因为挂错一张就是虚假宣传，而真正的买家会直接要证书 PDF。

## 8. 技术说明

### 首页动效（v0.2 新增）

国内站用的是 Swiper + GSAP + ScrollTrigger + three.js（一个地球模型）。这里做了同等体感、但**零依赖**的实现，不引任何库，首屏请求数和之前一样：

| 元素 | 行为 | 改哪里 |
|---|---|---|
| 全幅电站照片 | 铺满首屏，32 秒缓慢推近（Ken Burns），切走标签页不暂停但无性能负担 | 替换 `assets/img/hero-field.webp` 即可 |
| Hero 三屏文案轮播 | 7 秒自动切换，交叉淡入 + 文字逐行上浮 | `main.js` 里的 `DURATION`（毫秒） |
| 进度条 | 底部细绿线，随轮播走满 | CSS `@keyframes heroProgress` 的时长要和 `DURATION` 一致 |
| 控制方式 | 圆点 / 左右箭头 / 键盘 ←→ / 手机左右滑 | 自动绑定，无需配置 |
| 悬停暂停 | 鼠标进入 hero 或聚焦控件时停表，离开恢复并从当前屏重计 | `pause()` / `resume()` |
| 切走标签页 | 自动停表，切回来重计 | `visibilitychange` 监听 |
| 底部跑马灯 | 技术参数无限横向滚动，悬停暂停 | CSS `.marquee__track` 的 `46s` |
| 数字滚动 | 进入视口时从 0 数到目标值 | HTML 的 `data-count` / `data-dec` |

**关于背景照片**：用的是客户端提供的电站航拍图（1920×779）。有两处刻意的处理：

1. **产品图让位了。** 原来右侧浮着一张电池片特写，但电池片是深蓝、照片里的电站阵列也是深蓝，两者在视觉上完全融在一起——试过加玻璃卡片、提亮、加强发光，都救不回来（改成卡片会像一块平板屏幕）。所以 CSS 里用 `.hero__photo ~ .hero__slides .hero__figure { display: none }` 让它隐藏。**要恢复产品图，删掉这一行即可**，但建议同时换一张更亮的背景。

2. **双图层遮罩保证文字可读。** 一层 104° 斜向渐变（左侧 0.96 压暗给文字，右侧 0.30 让照片透出来），一层纵向渐变（顶部 0.88、底部 0.95，把照片压进页面背景色）。两个都调在 `.hero__veil` 里。

**换背景图**：直接替换 `assets/img/hero-field.webp`，同时更新 `hero-field-960.webp`（移动端）和 `index.html` 里 `<img>` 的 `srcset`。若新图比例差异大，调 `.hero__photo` 的 `object-position` 决定裁切重心。

**照片分辨率的限制**：原图 1920 宽，在 2× DPR 的 1440 屏幕上（物理 2880px）会略软。如果要更锐，需要一张 3000px 以上的原图。

**3D 网格背景已经撤掉**，但 CSS（`.hero__canvas`）和 JS（`main.js` 里的 3D IIFE）都还在——把 `<img class="hero__photo">` 换回 `<canvas id="heroCanvas">` 就能恢复。

**加第四屏**：复制一个 `<section class="slide">` 改内容，再在 `.hero__dots` 里加一个 `<button class="hero__dot" data-to="3">`，计数和 JS 会自动跟上（`slides.length` 是动态取的）。

**降级**：系统开启「减少动态效果」时（`prefers-reduced-motion`），轮播不自动播放、所有动画静态化，但手动切换仍可用。这条是硬约束，别为了动效删掉——欧盟客户里这个比例不低，而且 WCAG 2.1 有要求。

### 其它

- **无构建步骤**：改完 HTML 刷新就生效，外包/实习生都能维护
- **无外部依赖**：不加载任何 CDN 字体或 JS 库，首屏零阻塞请求
- **CSS 变量驱动**：主色 `--accent: #00D9A0`，改一行全站变色
- **响应式断点**：1080px / 760px
- **无障碍**：表单有 label 和 aria 属性，SVG 有 `role="img"` + `title`，轮播圆点有 `aria-selected`
- **已有结构化数据**：首页 Organization、组件页 Product，可继续加 BreadcrumbList 和 FAQPage

单页 HTML 里 `nav` 和 `footer` 是重复的（8 个页面各一份）。这是刻意的取舍：换来了"改一个文件就能上线"的简单性。如果后续页面超过 15 个，建议迁到 Astro + 组件化。
